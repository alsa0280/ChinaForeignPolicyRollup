03. START n8n IN DOCKER (WITH THIS REPO MOUNTED)
================================================

The repo folder is shared with the container at /home/node/.n8n-files.
The workflows use that path, so the mount must be exactly as below.

1. Open PowerShell and go to the repo folder, for example:

     cd C:\Users\YOURNAME\path\to\student-starter

2. Create storage for n8n's own data (workflows, tables, credentials).
   Do this once:

     docker volume create n8n_data

3. Download the image and start the container. ONE LINE (PowerShell):

     docker run -d --name n8n --restart unless-stopped -p 5678:5678 -v n8n_data:/home/node/.n8n -v "${PWD}:/home/node/.n8n-files" docker.n8n.io/n8nio/n8n

   macOS/Linux (Terminal):

     docker run -d --name n8n --restart unless-stopped -p 5678:5678 -v n8n_data:/home/node/.n8n -v "$PWD:/home/node/.n8n-files" docker.n8n.io/n8nio/n8n

   What the pieces mean:
     -d                          run in the background
     --name n8n                  name of the container
     -p 5678:5678                make n8n available at http://localhost:5678
     -v n8n_data:/home/node/.n8n keep n8n's data between restarts
     -v "<repo>:/home/node/.n8n-files"   share this repo with n8n
     docker.n8n.io/n8nio/n8n     the n8n image (downloaded the first time)

4. Open http://localhost:5678 in your browser. The first time, create the
   owner account (any email and password; it stays on your computer).

DAY-TO-DAY
   Stop:      docker stop n8n
   Start:     docker start n8n
   Logs:      docker logs n8n
   See state: docker ps -a

   Your data lives in the n8n_data volume, so stopping or restarting is safe.

START FROM SCRATCH (deletes ALL n8n data, workflows and tables)
   docker rm -f n8n
   docker volume rm n8n_data
   then repeat steps 2-3.

UPDATE n8n
   docker pull docker.n8n.io/n8nio/n8n
   docker rm -f n8n
   then repeat step 3 (keep the same n8n_data volume).

IMPORTANT
  The repo path in the -v option must be the repo you want to use. If you
  move the repo, remove the container (docker rm -f n8n) and run step 3 again
  from the new location. Data tables need a recent n8n version; use the
  latest image.
